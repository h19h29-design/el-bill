# 서울교육 전기요금 절감 진단·피크관리 플랫폼

학교 행정실 담당자가 월별 한전 고지서 데이터를 넣어 전기요금, 사용량, 최대수요전력, 요금제 변경 효과, 피크관리 가이드, 내부/한전 제출 문서 초안을 확인하는 시연용 React MVP입니다.

## 실행

```bash
npm install
npm run dev
```

검증:

```bash
npm run typecheck
npm run lint
npm run test
npm run build
npm run test:e2e
```

## 구현 범위

- React + TypeScript + Vite + Tailwind CSS 기반 브라우저 전용 앱
- 자동진단 흐름: 자동진단 시작 → 자료 업로드 → 학교정보 확인 → 요금제 자동 비교 → 피크관리 방안 생성 → 변경신청 패키지 생성
- 자동진단 결과 화면: 현재 요금제, 추천 요금제, 최근 12개월/3년 절감액, 피크 시나리오 반영 결과, 최종 판단, 다음 행동 버튼 제공
- Recharts 대시보드: 월별 전기요금, 사용량, 최대수요전력, 요금 구성
- ExcelJS 업로드 파서: 연도별 시트 자동 병합, 자동 인식 결과 확인, 적용 전 새 파일 미리보기, 수동 컬럼 매핑
- 한전 파워플래너 자료 가져오기: 사용자가 내려받거나 정리한 엑셀/CSV 업로드, 데이터 유형 선택, 컬럼 매핑
- 파워플래너 월별청구요금 HTML `.xls` 내보내기 파일의 연월, 사용전력량, 청구요금 자동 인식
- TanStack Table 기반 고지서 입력 내역 테이블
- React Hook Form + Zod 기반 피크/사용량 시나리오 입력 검증
- 현재 계약종별/수전전압/요금제를 기준으로 학교용 요금제 후보 TOP 3 자동 비교
- 고지서 기반 차액 추정과 요금표 기반 전체 추정을 분리한 확장 가능한 계산 엔진
- 목표/예상 피크 위험도 판정과 하계/동계/오늘 운영안 자동 생성
- 파워플래너 자료가 있으면 피크관리 화면에서 시간대별 사용량 그래프와 최대부하 시간대 위험도 표시
- 변경계획서, 한전 제출 공문, 변경신청서, 붙임 체크리스트, 계산 근거 요약표, 담당자 검토 필요 항목 패키지 생성
- Playwright E2E smoke: 자동진단, 업로드, 피크관리, 문서 ZIP/PDF 다운로드 흐름 검증
- Vercel 정적 배포 설정: `vercel.json`
- localStorage 최초 저장 기준 절대 24시간 TTL 및 만료 데이터 자동 삭제

## 자동진단 흐름

첫 화면의 `전기요금 자동진단 시작` 버튼을 누르면 사용자가 메뉴를 찾아다니지 않고 아래 순서대로 진행할 수 있습니다.

1. 자료 업로드: 한전 고지서 엑셀/CSV 또는 파워플래너 월별·일별·시간대별 자료를 브라우저에서만 읽습니다.
2. 자동 인식 결과 확인: 시트명, 연도, 필수 컬럼, 누락 컬럼, 자동 매핑 신뢰도를 확인하고 분석을 시작합니다.
3. 요금제 자동 비교: 현재 프로필의 계약종별, 수전전압, 현재 요금제를 기준으로 학교용 후보를 절감액 순으로 비교합니다.
4. 피크관리 방안 생성: 본관/별관 EHP, 강당, 급식실, 특별실, 제외 공간 정보를 반영해 운영안을 생성합니다.
5. 변경신청 패키지 생성: 실제 추천 요금제명과 절감액을 반영한 내부 계획서, 한전 공문, 신청서 미리보기, 체크리스트를 생성합니다.

첫 진입 시에는 기능 확인용 `시연 샘플` 상태를 표시합니다. 실제 한전고지서 또는 파워플래너 자료를 적용하면 `사용자 업로드 분석` 상태로 전환되며, 브라우저에 저장된 자료는 24시간 후 자동 삭제됩니다.

업로드 파일은 압축된 원본 10MB, XLSX 내부 항목 200개, 실제 압축 해제 출력 50MB, 전체 실제 행 10,000개, 시트당 256열까지만 브라우저에서 분석합니다. XLSX는 각 엔트리의 CRC32도 실제 출력으로 검증합니다. 새 파일을 선택한 직후에는 `새 파일 분석 미리보기`와 `현재 적용 데이터`를 분리해 표시하며, 분석 시작 버튼을 누르기 전까지 기존 진단 데이터는 변경하지 않습니다.

변경신청 패키지 ZIP에는 전기요금제 변경 계획(안), 한전 제출 공문, 전기사용계약 변경신청서 미리보기 PDF 3종이 포함됩니다. 계산 근거 요약표, 계산 분해표, 담당자 검토 항목, 신청서 자동입력 항목도 함께 제공합니다.

변경신청 문서는 최근 12개월 진단이 완료되고, 현재 계약종별·수전전압과 일치하는 후보가 `변경 추천`으로 판정된 경우에만 생성할 수 있습니다. 사업자등록증과 건축물관리대장처럼 앱이 실제 첨부 여부를 알 수 없는 항목은 자동 완료 처리하지 않습니다. 신청서 화면은 한전 공식 양식이 아닌 작성 참고용 미리보기입니다.

분석 결과에는 공식 청구액 계산기가 아니라 학교 내부 진단용 추정이라는 안내와, 요금제 변경 신청은 원칙적으로 1년에 한 번만 가능하므로 신중히 검토해야 한다는 안내를 계속 표시합니다.

## 데이터 검증과 보존

- 고지서 행은 `연도 + 월`의 달력 기준으로 정렬한다. 최근 12개월은 중복 없이 끊기지 않는 연속 12개월이어야 하며, 중복·누락·잘못된 월은 진단과 변경신청 문서 생성을 막고 수동 검토를 안내한다.
- 업로드에서 실제로 읽은 값은 `관측값`으로 기록한다. 요금적용전력 또는 요금 구성요소처럼 파일에 없는 선택 값은 현재 프로필과 유효한 요금제에서만 `추정값`으로 보완하며, 관측된 값처럼 표시하지 않는다. 최대수요전력은 계약전력이나 요금적용전력으로 대체하지 않는다.
- 파워플래너 자료는 피크 분석을 보강할 뿐 고지서 업로드 상태를 바꾸지 않는다. 따라서 파워플래너 파일만 올린 경우에는 시연 고지서 상태가 유지되고 변경신청 다운로드는 열리지 않는다.
- 사용자 고지서, 프로필, 피크 시나리오, 요금표, 파워플래너, 출처 정보는 `el-bill:storage-snapshot:<sessionId>`에 세션별 완전 스냅샷으로 저장한다. 새 업로드는 이름이 고정된 배타 Web Lock 안에서 스냅샷 저장·검증을 먼저 끝낸 뒤 `el-bill:storage-active` 포인터를 마지막에 전환한다. 저장 용량, 직렬화 또는 락 획득 실패 시 직전 활성 세션과 화면 상태가 유지된다.
- 일반 편집도 같은 Web Lock 안에서 최신 활성 스냅샷을 다시 읽고 변경된 최상위 필드만 병합한 뒤 `revision`을 증가시켜 저장·검증한다. 서로 다른 필드의 동시 변경은 함께 보존하고 같은 필드는 락 실행 순서의 마지막 변경을 적용한다. 초기화, 만료 정리, 레거시 마이그레이션도 같은 락을 사용하므로 오래된 탭이 새 세션을 되살리거나 새 업로드의 포인터를 지울 수 없다.
- Web Locks API가 없는 브라우저에서는 같은 탭 안의 작업만 Promise 큐로 직렬화한다. 이 대체 경로는 교차 탭 안전성을 보장하지 않으며 앱에서 다른 탭을 닫고 한 탭만 사용하라는 한국어 안내를 표시한다. 세션은 `0 < 만료-생성 <= 24시간`만 허용하며 만료 시 포인터를 먼저 해제하고 해당 세션 스냅샷을 삭제한 뒤 합성 시연 샘플로 돌아간다.

## 첨부파일 반영

- 사용자가 제공한 익명화 대상 자료에서 월별 청구 구조와 문서에 필요한 행정 항목을 검토했다.
- 공개 샘플은 실제 청구 행을 복제하지 않은 36개월 결정적 합성 데이터이며, 업로드 파서와 진단 흐름 검증에만 사용한다.
- 계획서, 공문, 변경신청서 자료의 일반적인 구성은 내부 계획안, 한전 제출 공문, 신청서 미리보기, 체크리스트 화면에 반영했다.
- 대시보드 화면 자료의 파란 사이드바, 흰 패널, 요약 카드, 차트/표 밀도와 색상 체계는 UI 참고용으로만 사용했다.

원본 파일은 repo에 복사하지 않았고, 현재 추적 콘텐츠에는 실제 학교명·고객번호·담당자·주소·연락처를 포함하지 않습니다. 이미 원격에 푸시된 과거 Git 이력의 재작성은 협업자의 커밋 해시를 변경하므로, 별도의 명시적 승인 없이 수행하지 않습니다.

## 주의사항

본 앱은 공식 청구액 계산기가 아니라 학교 내부 진단용 추정 도구입니다. 요금제 변경 신청은 원칙적으로 1년에 한 번만 가능하므로 예상 절감액, 피크 시나리오, 향후 사용량 변동을 신중히 검토한 뒤 진행해야 합니다.

한전 파워플래너 자료는 사용자가 직접 내려받거나 정리한 파일만 업로드합니다. MVP에서는 한전 계정 자동 로그인, 크롤링, 비공식 API 호출을 하지 않습니다. 파워플래너 사용 가능 여부는 한전 파워플래너에서 고객번호로 확인해야 하며, 고객번호는 한전 전기요금 청구서의 10자리 숫자입니다.

업로드는 `.xlsx`, `.csv`, 파워플래너 HTML 내보내기 `.xls`만 지원합니다. CFBF 매직 바이트를 가진 구형 바이너리 `.xls`는 파일명과 관계없이 파싱하지 않으며 XLSX 또는 CSV로 다시 저장하도록 안내합니다. XLSX는 중앙 디렉터리와 로컬 헤더를 검증하고 pako로 실제 해제 출력량과 CRC32를 확인한 뒤 ExcelJS에 전달합니다. ExcelJS는 표시값과 수식의 저장된 결과만 읽고 수식을 실행하지 않으며, 파일은 서버로 전송하지 않습니다. 운영 전 보완 계획은 `docs/upload-security-plan.md`에 정리했습니다.

`npm audit --omit=dev`의 최신 결과에는 ExcelJS의 Node용 전이 의존성 경로에 남은 항목이 있으므로, 이 MVP는 감사 결과가 깨끗하다고 주장하지 않습니다. 브라우저 전용 로컬 파싱 범위를 유지하고 실제 운영 전에는 대체 또는 격리 파서를 다시 검토해야 합니다.
