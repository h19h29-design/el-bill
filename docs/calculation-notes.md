# Calculation Notes

## 데이터 하네스

- 기본 샘플은 `2023-08`부터 `2026-07`까지 36개의 연속된 달을 생성하는 결정적 합성 데이터다.
- 사용량은 계절성, 연도별 완만한 증가, 월 인덱스 변동을 조합한 수식으로 생성한다. 실제 청구 행이나 실제 학교의 월별 사용 패턴을 보존하지 않는다.
- 기본요금, 계절별 전력량요금, 기후환경요금, 연료비조정액, 부가세, 전력산업기반기금은 아래 시연용 단가와 비율에서 계산하고 반올림한다.
- 모든 샘플 행의 비고는 `합성 시연 데이터`이며, 고객번호와 연락처는 마스킹한다.
- 사용자가 제공한 익명화 대상 자료와 원본 파일은 repo에 저장하지 않는다.

## 엑셀 파서

자동 병합 규칙:

1. 시트명에서 `20`, `21`, `22`, `23`, `24`, `25` 같은 연도를 찾는다.
2. `월분` 헤더가 있는 행을 찾는다.
3. 해당 학년도 열, `사용량(kwh)` 열을 찾는다.
4. 월, 사용량, 총 전기요금이 숫자로 확인되는 행만 `MonthlyBill`로 변환한다.
5. 실패하면 업로드 화면의 수동 컬럼 매핑을 사용한다.

필수 매핑은 연도, 월, 사용량, 총 전기요금이다. 요금적용전력, 최대수요전력, 기본요금, 전력량요금 등은 선택 매핑이며 누락 시 추정값을 쓴다.

### 달력 기간과 관측값 규칙

- 모든 고지서 행은 `연도 + 월`을 하나의 달력 기간으로 취급한다. 중복 기간은 한 번만 인정하고 중복 사실을 기록하며, 월이 `1..12` 범위를 벗어나면 진단에서 제외한다.
- 최근 12개월/3년 계산은 가장 최근 기간에서 거꾸로 이어지는 연속 구간만 사용한다. 예를 들어 2025년 12월 다음은 2026년 1월이며, 한 달이라도 비면 그 이전 행을 최근 연속 구간에 합치지 않는다.
- `usageKwh`, `totalBillWon` 등 실제 파일에서 매핑된 항목은 관측값이다. 누락된 요금적용전력은 활성 프로필의 값을 계산 보조값으로 쓸 수 있지만 관측값으로 표시하지 않는다. 누락된 최대수요전력은 `0`으로 유지하며 계약전력이나 요금적용전력으로 복사하지 않는다.
- 중복·누락·필수 항목 부족으로 최근 12개월이 성립하지 않으면 결과는 `추가 검토 필요`이고 변경신청 패키지 다운로드를 차단한다.

## 요금제 비교

요금 단가는 `src/data/ratePlans.ts`에 관리하며 UI 설정에서 수정 가능하다.

기본 고압A 단가:

| 구분 | 선택요금 I | 선택요금 II |
| --- | ---: | ---: |
| 기본요금 | 5,550원/kW | 6,370원/kW |
| 봄·가을철 | 86.5원/kWh | 82.1원/kWh |
| 여름철 | 123.3원/kWh | 118.8원/kWh |
| 겨울철 | 109.3원/kWh | 104.8원/kWh |

자동진단 후보 선정:

1. 학교 프로필의 계약종별, 수전전압, 현재 요금제명으로 현재 요금제를 찾는다.
2. 전체 요금표에서 `교육용` 계약종별 후보를 필터링한다.
3. 같은 계약종별/수전전압 후보를 우선 비교하고, 다른 학교용 요금제는 절감액과 무관하게 `추가 검토 필요`로 제한한다.
4. 최근 12개월 절감액을 기준으로 후보를 정렬하고 TOP 3를 결과 표에 표시한다.

계산 모드 A: 고지서 기반 차액 추정

- 기존 실제 총 청구액을 기준으로 삼는다.
- 현재 요금제와 후보 요금제의 기본요금 차액, 전력량요금 차액을 중심으로 절감액을 계산한다.
- 부가세, 전력산업기반기금, 기후환경요금, 연료비조정액 등은 기존 고지서의 기본요금+전력량요금 대비 비율로 보정한다.
- 실제 청구서 금액을 기준으로 하므로 공모전 MVP의 기본 자동진단 모드로 사용한다.

계산 모드 B: 요금표 기반 전체 추정

- 월 사용량, 요금적용전력, 계절별 단가표를 사용해 현재안과 후보안을 모두 다시 추정한다.
- 설정 화면에서 단가표와 보정계수를 수정할 수 있도록 유지한다.
- 단가표가 최신 한전 고시와 다를 수 있으므로 공식 청구액 계산이 아니라 내부 진단용 비교로만 사용한다.

공통 계산 흐름:

1. 월 사용시간 = 월 사용량 kWh / 요금적용전력 kW
2. 계절별 전력량 단가를 적용
3. 예상 최대수요전력 입력값이 있으면 기본요금 산정 전력에 반영
4. 전체/여름/겨울 사용량 증가율을 반영
5. 기후환경요금, 연료비조정액, 부가세, 전력산업기반기금은 진단용 추정 계수로 반영
6. 최근 12개월과 최근 3년 기준으로 현재안과 변경안을 비교

결과 화면과 문서 패키지에는 최근 12개월 기준 계산 근거를 다음 항목으로 분해해 표시한다.

- 기본요금 차액
- 전력량요금 차액
- 부가요금/보정
- 최근 12개월 합계

계산 신뢰도:

- `데이터 충분`: 최근 36개월 이상 자료가 있고 최대수요전력 컬럼이 모두 확인됨
- `보통`: 최근 12개월 이상 자료가 확인됨
- `낮음`: 12개월 미만이거나 필수 컬럼이 부족함

판정:

- 12개월 데이터가 없으면 `추가 검토 필요`
- 최근 12개월과 최근 3년 모두 절감이면 `변경 추천`
- 변경 시 증가하면 `유지 추천`
- 나머지는 `추가 검토 필요`

대시보드, 자동진단 결과, 문서 패키지는 모두 자동진단의 동일한 계산 모드와 비교 결과를 사용한다. 다른 계약종별 또는 수전전압 후보는 계산상 절감되더라도 변경신청 문서 생성 대상이 아니다.

## 피크관리

위험도:

- 80% 미만: 안전
- 80% 이상 90% 미만: 주의
- 90% 이상 95% 미만: 경고
- 95% 이상: 위험

검증 기준인 목표 500kW, 예상 485kW는 97%로 계산되며 `위험`으로 표시된다.

자동 운영안은 설정한 본관·별관 EHP 그룹을 13:00부터 5분 간격으로 모두 열거한다. 하계·동계 최대부하 시간대와 급식실, 특별실, 강당 운영시간을 같은 화면에 표시해 동시 기동 위험을 검토한다.

## 한전 파워플래너 자료

앱은 한전 파워플래너를 대체하지 않고, 학교 행정실 업무에 맞게 파워플래너/한전고지서 자료를 재분석하는 보조 플랫폼이다.

MVP 원칙:

- 한전 계정 자동 로그인 금지
- 크롤링 금지
- 비공식 API 호출 금지
- 사용자가 파워플래너에서 내려받거나 정리한 엑셀/CSV만 업로드
- 시연용 데이터는 기존 정책대로 24시간 후 자동 삭제

업로드 가능한 데이터 유형:

1. 월별 사용량
2. 일별 사용량
3. 시간대별 사용량
4. 최대수요전력
5. 예상요금
6. 소비패턴 분석 결과

파워플래너 자료가 있으면 피크관리 화면에서 시간대별 사용량 그래프와 최대부하 시간대 위험도를 추가로 표시한다. 자료가 없으면 기존 한전 고지서 월별 데이터와 예상 피크 입력값만으로 진단한다.

파워플래너의 `월별청구요금.xls`는 실제 바이너리 엑셀이 아니라 HTML 표를 `.xls` 확장자로 내려주는 형식일 수 있다. 공통 업로드 파서는 이 형식을 감지해 `연월`, `계약전력(kW)`, `요금적용전력(kW)`, `사용전력량(kWh)`, `사용일수(일)`, `지상역률(%)`, `진상역률(%)`, `청구요금(원)` 헤더와 행을 복원한다. 고지서 입력 화면에서는 월별 청구요금 행으로 자동 변환하고, 파워플래너 자료 가져오기 화면에서는 `연월` 기반 월별 사용량으로 자동 매핑한다.

향후 공식 API 또는 기관 연계가 가능할 경우를 대비해 `DataSource<TRecord>`와 `PowerPlannerDataSource` 타입을 분리했다. 현재 구현은 `provider: 'kepco-power-planner'`인 사용자 업로드 출처만 사용한다.

## 문서 생성

첨부 계획서/PDF 공문에서 확인한 구조를 바탕으로 다음 문서를 생성한다.

- 내부 결재용 변경 계획(안)
- 한전 제출 공문
- 전기사용계약 변경신청서 미리보기
- 붙임 체크리스트
- 계산 근거 요약표
- 담당자 검토 필요 항목 목록

모든 문서에는 내부 진단용 추정, 요금제 변경 신청은 원칙적으로 1년에 한 번만 가능하므로 예상 절감액과 피크 시나리오를 신중히 검토해야 한다는 문구, 실제 제출 전 담당자 검토 필요 문구를 포함한다.

변경신청 문서는 `변경 추천`이면서 현재 계약조건과 일치하는 후보일 때만 다운로드할 수 있다. 붙임 체크리스트의 사업자등록증·건축물관리대장은 사용자가 실제 첨부했는지 앱이 알 수 없으므로 `첨부 확인`으로 표시하며, 변경신청서 미리보기에는 한전 공식 양식이 아니라는 안내를 표시한다.

문서 다운로드를 열기 위한 조건은 다음과 같다.

1. 사용자 고지서 업로드 출처여야 한다. 파워플래너만 올린 경우에는 피크 분석은 가능하지만 고지서 출처는 시연 샘플로 남는다.
2. 최근 12개의 서로 다른 달력 기간이 끊기지 않고 이어져야 한다.
3. 현재 계약종별·수전전압·요금제명이 요금표의 단 하나의 행과 정확히 일치해야 한다.
4. 동일 조건 후보의 최종 판단이 `변경 추천`이어야 한다.

사용자 저장값은 `el-bill:storage-snapshot` 한 키에 스키마 버전, 24시간 절대 만료 세션, 고지서, 프로필, 피크 시나리오, 요금표, 파워플래너, 출처 정보를 모두 포함한 완전한 스냅샷으로 관리한다. 고지서 또는 파워플래너 파일 적용은 직렬화와 검증을 마친 뒤 단 한 번의 localStorage 쓰기를 커밋 경계로 사용하며, 쓰기 실패 시 기존 스냅샷과 화면의 업로드 상태를 유지한다. 프로필·시나리오·요금표 편집은 현재 세션 ID를 다시 확인한 뒤 전체 루트를 갱신하고 기존 만료 시각을 유지한다.

앱 최초 복원은 React 지연 초기화에서 한 번만 수행한다. 손상되거나 불완전하거나 만료된 루트는 사용하지 않으며, 다른 탭의 더 새 세션을 오래된 탭이 덮어쓰거나 삭제하지 못하도록 세션 ID와 커밋 직전 루트 원문을 비교한다. `storage` 이벤트와 포커스·가시성 복귀 시 유효한 새 루트를 통째로 채택하고, 삭제 또는 만료가 확인되면 합성 시연 샘플을 복원한다. 구버전 개별 키와 `storage-session`/`storage-commit` 데이터는 가장 이른 기존 만료 시각을 유지해 한 번만 원자적으로 마이그레이션하며, 루트 저장 성공 후에만 구버전 키를 제거한다.
